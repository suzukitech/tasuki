# UI レビュー基準

`docs/DESIGN.md` の「画面デザイン」が正本。ここはレビュー時に機械的に確かめられる形に落とした基準です。トークンは `apps/web/src/styles.css`。

## 基準

1. **誰の番かが最初に見える**: 一覧の各行と詳細パネルに「あなたの番」「AIの番」「他の人の番」のバッジがある。「あなたの番」だけが赤で、他の赤（`--sash`）は人間ゲートの強調とエラーに限る。
2. **襷は2か所だけ**: 斜めの縞（`repeating-linear-gradient(135deg, ...)`）が出るのは「あなたの番」バッジの先頭と、ボードの人間ゲート列の見出しだけ。それ以外に縞や似た装飾がない。
3. **色**: 背景は紙 `#F7F8F6`、面は `#FFFFFF`。主操作・選択・リンクは藍、AIの番は浅葱。これ以外の彩色、グラデーション、装飾的な影がない（浮かぶサイドパネルの薄い影を除く）。
4. **文字**: BIZ UDPGothic（400/700）のみ。基本14px、日本語本文の行間1.6。サイズは 12/13/14/16/20/24px から選ぶ。チケット番号、件数、日付は等幅数字（tabular-nums）。
5. **使わない表現**: 等幅のラベル、英大文字、中黒でつないだメタ情報、ボタン文言の矢印、同じ角丸カードの並び。
6. **コントラスト**: 補助文字（鼠）を含め、本文は背景に対してAA（4.5:1）以上。色だけで状態を伝えない（バッジは文言を持つ）。
7. **フォーカス**: キーボードで辿れるすべての要素で、藍のフォーカスリングが見える。`prefers-reduced-motion` で動きが止まる。動くのはパネルの開閉だけ。
8. **レイアウト**: 左サイドバー224px。メインは左寄せの密な表。パネルは約540px、1280px以上で一覧を押し、それ未満は一覧に重なる。390px幅ではサイドバーが上部バーになり、パネルは全画面で、横スクロールが出ない。
9. **文言**: 平易な日本語。ボタンは動詞で言い切る（「計画を承認する」「差し戻す」「完了にする」「コメントする」）。エラーは「何が起きたか」と「どうすればよいか」。空の状態は次の行動に誘う。
10. **キーボード**: C、J/K、Enter、Esc、`/` が動く。入力欄の中とIME変換中は動かない。すべての操作がマウスだけでもできる。

## 画面と状態

各画面を desktop / laptop / mobile で確かめる。

- setup: ユーザーが0人のときの最初の管理者作成。作成済みのサーバーでは案内だけが出る。
- login: 通常、ログイン失敗（文言が原因と対処を言っている）。
- invite: 招待リンクからのアカウント作成。無効なリンクのエラー。
- 一覧 空: 「チケットはまだありません。C キーでタイトルだけ入れて作れます」と作成欄。
- 一覧 データあり: 状態、担当、優先度のセルをクリックしてその場で編集できる。選択行（J/K）のフォーカスが見える。「さらに読み込む」。検索に合う行がないときの空表示。
- レビューキュー: 件数がサイドバーに出る。空のとき案内が出る。
- パネル 依頼タブ: タイトル、本文、受け入れ条件の編集、項目。
- パネル 計画タブ: 計画なし。計画あり（AIの理解が先頭、左に受け入れ条件・右に手順、手順のない条件に警告）。
- パネル 計画タブ plan_review を承認者として開く: 「計画を承認する」「差し戻す」が出る。差し戻す理由が空だと送れない。
- パネル 計画タブ plan_review を承認者でない人として開く: ボタンが出ない。
- パネル レポートタブ: レポートなし。あり（3行要約、AIの判断、逸脱、条件ごとの結果と証拠、テスト、PR）。impl_review の承認者には「完了にする」「差し戻す」。
- パネル 会話・履歴タブ: 回答待ちの質問と回答欄、コメント、履歴（「Claude Code経由」「CLI経由」「Web」の表示）。
- 412 トースト: 別のタブで更新してからセルを編集すると、「他の人が先に更新しました。最新の内容を読み込みました」が出て、表が最新に戻る。
